02 Priority 1 — Production Basics

These must be done before going live. Highest impact, lowest complexity.

2.1 Environment & Secrets Management

✅ Done Profiles split into application-dev.yaml (local DB) and application-prod.yaml (env vars). Default active profile: dev. 
# application.yaml
spring:
  profiles:
    active: dev

# Run dev (default)
./mvnw spring-boot:run

# Run production profile
./mvnw spring-boot:run -Dspring-boot.run.profiles=prod

# Or via env var
export SPRING_PROFILES_ACTIVE=prod
Optional next step: On AWS EC2 use Secrets Manager or Parameter Store for prod env vars.

2.2 Database Migrations — Flyway

✅ Done Flyway enabled with versioned migrations in src/main/resources/db/migration/. Dev profile uses ddl-auto: validate so Hibernate checks the schema without auto-altering it. 
# Applied migrations
V1__init_schema.sql          — full initial schema
V2__add_user_test_column.sql — ALTER TABLE user ADD COLUMN test

# application-dev.yaml
spring:
  jpa.hibernate.ddl-auto: validate
  flyway:
    enabled: true
    locations: classpath:db/migration

# Rule: never edit applied migrations — add V3, V4, etc.
Dev tip: If you edit an already-applied migration locally, run flyway repair to fix checksum mismatches before restarting the app.

2.3 Pagination

✅ Done GET /api/v1/products/getAllProducts returns a Spring Data Page with @PageableDefault(page = 0, size = 10, sort = "prodId"). 
# Example requests
GET /api/v1/products/getAllProducts?page=0&size=10
GET /api/v1/products/getAllProducts?page=1&size=20&sort=prodId,desc

# Response includes content, totalElements, totalPages, number, size
Optional next step: Add pagination to getAllCategories when the category list grows.

2.4 API Documentation — Swagger

08 Exception Handling — Full Guide

8.1 Current vs Target

ExceptionHTTP StatusStatus
ResourceNotFoundException404Done
MethodArgumentNotValidException400Done
IllegalArgumentException400Done
DataIntegrityViolationException409Should be 409
Exception (catch-all)500Leaks internals
BadCredentialsException401Missing
AccessDeniedException403Missing
DuplicateResourceException409Missing
BusinessRuleException422Missing

8.2 Target Exception Hierarchy

Exception/ ├── GlobalExceptionHandler.java ├── ApiException.java (abstract base) ├── ErrorCode.java (enum of all error codes) ├── ResourceNotFoundException.java 404 ├── DuplicateResourceException.java 409 — SKU already exists ├── BusinessRuleException.java 422 — business logic failed ├── UnauthorizedException.java 401 ├── ForbiddenException.java 403 └── dto/ ├── ApiErrorResponse.java └── ValidationErrorResponse.java

8.3 Unified Error Response Format

{
  "status": 404,
  "error": "Not Found",
  "code": "PRODUCT_NOT_FOUND",
  "message": "Product not found with id: 5",
  "path": "/api/v1/products/getProduct/5",
  "traceId": "a1b2c3d4-e5f6-7890",
  "timestamp": "2026-08-22T15:38:00"
}

8.4 Logging Rules

HTTP StatusLog LevelClient Message
400, 404, 409, 422WARNSpecific, helpful message
401, 403WARNGeneric auth message
500ERROR + full stack traceGeneric + traceId only

❌ Never do this on 500

"An unexpected error occurred: "
  + ex.getMessage()

Leaks SQL errors, file paths, internal details.

✅ Do this instead

log.error("[{}] Unhandled at {} {}",
  traceId, method, path, ex);
return "Contact support with traceId: "
  + traceId;

8.5 How to Throw in Service Layer

❌ Before (current)

throw new IllegalArgumentException(
  "SKU already exists");

.orElseThrow(() ->
  new ResourceNotFoundException(
    "Product not found..."));

✅ After (standard)

throw new DuplicateResourceException(
  ErrorCode.SKU_DUPLICATE,
  "SKU '" + sku + "' exists");

.orElseThrow(() ->
  new ResourceNotFoundException(
    ErrorCode.PRODUCT_NOT_FOUND,
    "Product not found: " + id));
Rule: Controllers should have zero try/catch — all exceptions bubble up to GlobalExceptionHandler.

8.6 Implementation Order

  1. Unified ApiErrorResponse record (status, code, message, path, traceId, timestamp)
  2. ErrorCode enum
  3. ApiException base class
  4. DuplicateResourceException (409) — replace SKU IllegalArgumentException
  5. Security handlers (401, 403) + AuthenticationEntryPoint
  6. HttpMessageNotReadableException + MethodArgumentTypeMismatchException
  7. Logging + hide 500 internals + traceId
  8. BusinessRuleException (422)

09 DTO vs Entity Strategy

ConcernEntity (ProdData)DTO (Req/Res)
DB persistence✅❌
API validation❌✅ @NotBlank, @Valid
Hide internal fields❌✅ (no Internal in response)
API stability❌ (changes with DB)✅

Recommended Pattern

OperationDTONotes
CreateFull Req_DTO with validationAll required fields
UpdateSame Req_DTO + MapStruct IGNORE nullsPartial update — send only changed fields
ResponseRes_DTOHide sensitive / internal fields
ListRes_DTO (paginated)Never return full entity

What NOT to Do

ApproachVerdictReason
Map<String, Object> as request bodyAvoidNo validation, security risk
Entity directly as @RequestBodyAvoidExposes DB structure, mass assignment
Generics to skip DTO updatesAvoidGenerics still need concrete types

10 Elasticsearch Integration

MySQL (source of truth) ↓ sync on create / update / delete Elasticsearch (search index) ↑ query SearchController → GET /api/v1/products/search?q=...

Index Fields (MVP)

FieldES TypeSearch Weight
offeringNametextHighest (^3)
brandtextHigh (^2)
tagstextMedium
shortDesctextMedium
skuIdkeywordExact match only
categorykeywordFilter
sellingPricefloatFilter + sort
featuredOfferbooleanRelevance boost
Important: Do NOT also implement MySQL FULLTEXT. Elasticsearch replaces the search layer entirely. MySQL remains for CRUD only.
